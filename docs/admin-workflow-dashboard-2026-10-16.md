# لوحة مسارات الوكلاء والمهام

المسار: `/admin/workflows` ضمن لوحة المدير. الصفحة تستخدم نمط المنصة الداكن والزجاجي، وجدول المهام، وشجرة المسار، والبحث والتصفية واختيار الطلب، مع ألوان ثابتة: العميل أزرق، والمنسّق أخضر، والتخصصات أصفر، والمخرجات بنفسجي.

## مصدر الحالة الفعلية

- قراءة فقط من `/api/admin/content-imports` عبر وكيل الواجهة الحالي؛ يتولى `requireAdmin` الموجود في الخادم فرض الصلاحية. لا مسار كتابة أو صلاحية أو جدول جديد.
- التحديث كل 15 ثانية عندما تكون الصفحة ظاهرة. لا طلبات متداخلة؛ تُلغى القراءات عند الانتقال للمحاكاة أو مغادرة الصفحة. تعرض الصفحة وقت آخر قراءة ناجحة، وتمسح البيانات عند 401/403.
- تعرض آخر 100 طلب حسب حد واجهة الخادم الحالية؛ الأعداد تخص المسار المحدد، وليست عدد أشخاص أو وكلاء متصلين.
- المراحل: قراءة المصدر، وتصنيف المحتوى، وتوليد الأسئلة، وحفظ المحتوى والاختبارات. النسبة هي عدد المراحل المكتملة ÷ 4. المرحلة الجارية لا تحتسب مكتملة: `reading=0%`, `classifying=25%`, `generating=50%`, `saving=75%`, `completed=100%`.
- في حالة الفشل أو مرحلة غير معروفة، لا يكشف العقد الحالي آخر مرحلة مكتملة؛ لذلك تعرض النسبة «غير مقاس» بدل اختلاق رقم. الرفع الجاري لا يعرض نسبة بايتات غير متاحة.
- المنسّق والأدوار هنا مكونات مسار المعالجة داخل المنصة، وليست اتصالات حية بجلسة Codex أو Claude. لا تدّعي الصفحة رصد وكلاء المحادثة.

## المحاكاة

مثال مستقل محلي للعميل والمنسّق والبحث والبرمجة والجودة والتسليم. زر التقدم يزيد المرحلة الحالية 25 نقطة، ولا يبدأ الدور اللاحق حتى يكتمل السابق. نسبة المنسّق تحسب من المراحل الأربع. إعادة الضبط محلية؛ لا استدعاء نموذج أو إنشاء مهمة أو نشر فعلي.

## التحقق

اختبارات نموذج المراحل وعدم التخمين وترتيب الاعتماديات، واختبارات الواجهة لعزل المحاكاة، والبحث، وفقدان الصلاحية، والفشل، والحالة الفارغة، وإلغاء الطلبات المتأخرة. تعتمد حماية الصفحة على تخطيط الإدارة الحالي، وتبقى حماية البيانات مستقلة في الخادم.
